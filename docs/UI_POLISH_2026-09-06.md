# Notification, Audio, Center and Settings polish

This change adapts existing Titonium components and contracts; no external implementation was copied.

- Connected popups reserve a consistent 48px outer gutter: two opposing 16px shoulders and 16px of clear space. The shared popup shoulder mirrors ScreenCorner, and one contour paints the rail and body without a second background. Narrow screens clamp the inset while retaining a positive viewport. Left application menus retain source centering within the same minimum gutter.
- Topbar source controls remain in their row slots for every popup. Opening Input Method no longer translates its icon toward the popup center, so it cannot overlap the adjacent connectivity icons.
- Active Window removes a trailing application-name segment, preserves the tab title, and caps the pill at 380 logical pixels with an elided flexible title.
- Notification history groups by source plus application identity. The newest entry represents a collapsed group; its header or card expands the group. Actions and dismissal retain the original notification key. The history viewport requests 560px; the connected host caps content at 680px and clamps to the output.
- Connected Audio requests up to three complete 72px application rows without deriving its natural height from the animated host. Applications open by default. Live volume changes retain delegates through a stable stream-ID model, with volume and mute resolved through AudioService.
- Connected Center retains Compact as a title pill above both Normal and Expanded, reserving a 12px gap. The chassis opens from Compact dimensions, while content stays clipped below the title. Classic already retains its detached Compact title.
- Settings closes from a button inset 6px from the top-right corner. The redundant footer Cancel button is removed. Editable pages reset only their owned fields; About has no reset action. Global defaults are at the footer left. Both resets remain staged until Apply; closing still follows the existing discard flow. Appearance and shared Reduced Motion changes retain the appearance transaction boundary.

Validation: `scripts/check.sh` passed, including new grouping/title/reset fixtures, QML live-drag and notification action tests, 18 coordinator tests, and Center transition coverage. Foreground smoke, protected acceptance and audio acceptance passed from an isolated source copy; `hyprctl configerrors` was empty. The protected suite skipped native notification acceptance because the resident notification server owned the D-Bus name. Notification grouping/actions were exercised with the production QML views against a fixture coordinator.

## Gap and icon regression checks

`check_edge_contour.py` verifies a clear gap between two actual rendered shoulder curves, continuation of the gap below them, the rounded lower corner and the tall body fill. Geometry fixtures cover differing popup widths, different source controls, left menus and narrow outputs. The composition contract rejects source-only icon translation. A temporary native test shell opened the real Input Method menu and measured its icon at x=2332 before and x=2332 after opening; the menu screenshot showed distinct Input Method, pin, network, Bluetooth, audio and notification controls at DP-1 scale 1.5.

## Explicit topbar unpin

A successful unpin now requests immediate hiding and ignores the existing pointer hover until it leaves. Fresh edge entry reveals the bar again; pinning restores it. The surface router closes bar menus and returns Center to compact on that explicit action. Preference changes still use the existing preview/commit transaction.

Validation: visibility rule fixtures cover held hover and fresh entry; transaction fixtures cover accepted/rejected preview and committed toggles. A native temporary shell exercised the real pin button with held hover, fresh entry, and repinning (all passed).
